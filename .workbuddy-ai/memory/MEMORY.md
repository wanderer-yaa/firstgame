## 项目

一句话：用一具凡人的身体，在有限的一生里，走到世界的尽头。

## 角色分工

**本文件不指定"我是谁"。你属于哪个角色，由你的 agent 配置决定。** 读完这张表，按你的角色看对应列。

| 角色     | 负责                          | 不做什么           | 主要产出                |
| ------ | --------------------------- | -------------- | ------------------- |
| **设计** | 出规格、定验收标准、判"是否符合设计意图"、补规格空白 | 不写代码、不跑测试、不改实现 | `docs/设计/` 下的规格书    |
| **制作** | 实现、自检、产出证据、调 B 类数值          | 不改 A 类规则、不改规格  | `game/` 下的代码与资产     |
| **审查** | 按验收标准逐条验、核对证据、出结论           | 不参与设计、不改代码     | `docs/审查记录/` 下的验收报告 |
| **用户** | 拍板、最终验收、冲突仲裁                | —              | —                   |

详细职责与交接规则见 `docs/协作约定.md`。

## 分工原则（2026-10-24 确立）

> **分工不该按"你做什么"分，该按"错了会怎样"分。**

| 错了会怎样                       | 处理          |
| --------------------------- | ----------- |
| 毁掉整套设计（寿元模型、突破规则、存档格式、时间推进） | 必须写死，制作不能改  |
| 只是重做一遍（UI 布局、场景、文案、动画）      | 放给制作自定，不进规格 |

规格只写"不可推断"的部分：规则、数值、验收方式。写之前先问：**这条错了会毁设计吗？** 不会就别写。

审查不设常驻角色，改为"交付后的一次独立复核"（关键：复核上下文不是写代码的那个）。M1 之后再考虑独立。

## 用户偏好

- 要求设计有批判性，不要草率认同；埋雷要早说，给清晰的差分目标。
- 设定必须有可推敲性（能推出什么 / 是否自洽 / 玩家能否感知）。
- 反感"数字面板式"的修仙表达，沉浸感优先。
- 世界观未定调，通过切片逐步定；拒绝过早编具体名词。
