> 版本：v1.0　更新：2026-10-24

## 0. 这份文件管什么

只写三样东西：

| 类 | 内容 | 制作能不能改 |
|---|---|---|
| **A 规则** | 时间、寿元、突破、存档这类"错了就毁设计"的 | **不能改** |
| **B 数值** | 需求、产出、概率、耗时 | 可以调，但要记录 |
| **C 实现** | UI、架构、命名、脚本、动画 | **制作自定，不要问设计** |

**判断标准：这条写错了，会不会毁掉设计？** 会 → 写进 A；不会 → 归 C，不进规格。

按这个标准，下面关于"界面长什么样""按钮放哪""代码怎么组织"的，一律不写。

---

## 1. M0 验证什么

只验证一件事：

> **玩家会不会在"要不要现在突破"这一刻犹豫。**

不是验证功能多不多，不是验证画面好不好。功能再全，如果那一刻不纠结，这套数值就是失败的。

配套判断：到三层用时 4–6 分钟；失败后想再试而不是想关；玩完能用"年"说出玩了多久，而不是"十几分钟"。

---

## 2. 范围

**做**：时间推进 / 4 种资源 / 打坐与采药 / 炼气一至四层 / 一次会失败的突破 / 寿元 / 存档与离线 / 事件接口空实现。

**不做**：背包 UI、炼丹、战斗、天赋六维、气运、玄学、宗门、道友、剧情、美术、多语言、设置。

---

## 3. A 类：不可改的规则

### A1 时间

| 规则 | 说明 |
|---|---|
| 单位 | 日。1 年 = 365 日 |
| 速率 | **1 现实秒 = 1 游戏日**（1× 速度） |
| 推进条件 | **有活动在进行，且未暂停**。空闲时时间静止 |
| 倍速 | 2× / 4× 只改变游戏日推进速度 |

"空闲时时间静止"是硬规则——它是"时间只在行动中流逝"的实现。不能改成"永远在走"。

### A2 寿元

```
剩余 = 上限 − 已用年数 − 根基损伤
已用年数 = 游戏总天数 / 365
```

| 规则 | 说明 |
|---|---|
| 上限来源 | 由境界决定（炼气 120 年），**不由灵根决定** |
| 减少方式 | 只有两种：时间流逝、上限被损伤 |
| **玩家不能"花寿元"** | 任何按钮都不标价"耗寿 N 年" |
| 损伤 | 突破失败 −10 年，**不可恢复** |
| 归零 | 坐化，游戏结束 |

这是整套设计的分水岭。**"扣寿元"和"损伤上限"是两回事**：前者是消费，后者是钟被砸短。实现时不要图省事合并成一个字段。

### A3 修为与升层

| 规则 | 说明 |
|---|---|
| 修为只增不减 | 唯一例外：突破失败倒退 30% |
| 修为满后停止累积 | 不溢出，不自动突破 |
| 小层自动升 | 一→二、二→三 达标即升，**不需要按钮** |
| 坎才需要决策 | 只有"三层→四层"需要玩家点突破 |

**小层自动升**是硬规则。如果每层都要点按钮，玩家会在十分钟内点九次，那就不是"坎"，是流水线。

### A4 突破

| 规则 | 说明 |
|---|---|
| 判定时机 | 玩家确认的那一瞬间 |
| 随机种子 | **一次性，立即写入存档** |
| 读档 | **不重算**。种子已在存档里 |
| 显示 | **区间，不是精确值** |
| 结果 | 三档：成功 / 失败 / 走火入魔 |

**成功率构成**：基础值 + 辅助加成 + 一个不可控随机偏移（−8% ~ +8%）。

**显示的是"基础+辅助"的区间（真实值 ±8%），玩家永远不知道精确值。** 这条不能改——改成精确值，突破就退化成资源检查表。

**种子锁定不能省。** 单机 + 手动存档，如果不锁，玩家会 SL 到成功，"突破必须失败"这条铁律直接归零。

### A5 活动

| 规则 | 说明 |
|---|---|
| 同时只能有一个 | 违反即报错，不静默处理 |
| 切换时进度保留 50% | 防止无脑来回切 |
| 进度按游戏日推进 | 不按现实时间 |

### A6 存档与离线

| 规则 | 说明 |
|---|---|
| 格式 | JSON，含 `version` 字段 |
| 时机 | 每 60 秒自动 + 关键节点（突破/升层/退出） |
| **离线不推进游戏日** | 也不消耗寿元 |
| 离线结算 | 按当前活动产出 × 时长 × **50% 效率**，上限 8 小时 |
| 离线回执 | 启动时必须给出，写明离开多久、得了什么 |

**为什么离线不推进时间**：1 秒 = 1 日的速率下，离线 8 小时等于 79 年，玩家一觉醒来就老死。离线必须与在线脱钩，这是唯一不惩罚玩家的做法。

**必须保留的字段**（名字可改，语义不能丢）：`version`、`game_days`、`realm.index`、`realm.tier`、`resources`、`lifespan.cap`、`lifespan.damage`、`activity`、`flags`、`pending_breakthrough_seed`。

## 4. B 类：可调的数值

制作可以调，但每次调整要记一行：改了什么、为什么、改完 A2 的用时变成多少。

| 项 | 初值 |
|---|---|
| 炼气 1→2 需求 / 基础产出 | 60 / 1.5 每秒 |
| 炼气 2→3 需求 / 基础产出 | 130 / 2.0 每秒 |
| 炼气 3→4 需求 / 基础产出 | 270 / 2.7 每秒 |
| 灵根契合系数 | 0.8 |
| 三层突破基础成功率 | 65% |
| 安神草 5 株加成 | +8% |
| 采药耗时 / 成功率 / 产出 | 30 日 / 70% / 1–2 株 |
| 突破失败：修为倒退 / 卧床 / 上限损伤 | 30% / 180 日 / 10 年 |
| 走火入魔占失败比例 | 20% |
| 离线上限 / 效率 | 8 小时 / 50% |

**可调的是数字，不是结构。** 你可以把成功率调到 80%，但不能改成"显示精确值"。

## 5. C 类：制作自定

以下**不要问设计**，自己定，定完不用报备：

- 界面长什么样、控件怎么摆、配色字体
- 场景与节点结构、代码架构、命名规范
- 日志格式、测试脚本怎么写
- 存档文件的具体文件名与目录
- 动画、音效、过渡效果
- 加载流程、错误提示的文案

**唯一要求**：修为条默认不显示数字（这是 A2"玩家不能花寿元"的配套——数字会把体验翻译成报表）。用填充度或光晕表示，悬停再显示精确值。

## 6. 验收：只验 A 类

B 类数值不验（调了也算过），C 类不验（制作说了算）。

| # | 验什么 | 怎么判 |
|---|---|---|
| V1 | 暂停后时间、修为、进度全停 | 暂停 30 秒，存档 `game_days` 不变 |
| V2 | 4× 产出是 1× 的 4 倍 | 各跑 60 秒对比，误差 <2% |
| V3 | 小层自动升，三层才出现突破按钮 | 操作观察 |
| V4 | 突破显示区间，无精确数字 | 截图 |
| V5 | 读档重试突破，结果不变 | 连续读档 5 次 |
| V6 | 失败后：修为 −30%、上限 −10 年、跳过 180 日 | 存档 diff |
| V7 | 离线：有回执、资源增加、**寿元不变** | 改系统时间 |
| V8 | 在线与离线同等时长，资源误差 <1% | 对比 |
| V9 | 修为条默认无数字 | 截图（默认态 / 悬停态） |

**V5 和 V7 是两条命门。** 前者防 SL，后者防"离线惩罚"。这两条过了，M0 的骨架就没错。

**证据**：V1/V2/V6/V8 用存档 diff 或脚本日志；V4/V9 用截图；V3 用录屏；V5 用连续日志。

### 手感（人工，用户与复核者判断）

| # | 判据 |
|---|---|
| B1 | 连续玩 15 分钟不中断 |
| B2 | **中途至少产生一次"要不要现在突破"的犹豫** |
| B3 | 失败后想再试，而不是想关 |
| B4 | 能用"年"说出玩了多久 |

**B2 是 M0 唯一的核心指标。** 其余全过、B2 不过，等于失败。

## 7. 接口预留（不实现，但要存在）

| 接口 | 为什么 |
|---|---|
| `flags` 字典 | 事件系统的一切条件判断都靠它 |
| 条件求值器 | 事件、解锁、UI 显隐共用一套语法 |
| 活动可打断 | 事件要能中断修炼 |
| 五个触发点空函数 | 活动完成 / 突破成败 / 进新地点 / 每月 / 寿元阈值 |
| `version` 字段 | 存档迁移的前提 |
| `system: "qi"` 字段 | 以后加体修、血修不改存档 |

## 8. 已知风险

| 风险 | 判断 |
|---|---|
| 4.2 分钟到三层可能太快 | 玩家未投入就遇坎。备选：需求整体 ×1.5 |
| 采药 2.5 分钟换 8% 可能不划算 | 最可能出问题的一条，B2 不通过时先查这里 |
| 三层→四层奖励太弱 | 只给"内视"（UI 解锁）感知弱。备选：产出 +30% |
| 离线不推进时间可能显得假 | 接受。正式版再解 |
