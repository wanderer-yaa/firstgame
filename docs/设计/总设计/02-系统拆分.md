# 02 · 系统拆分

> 版本：v2.0　更新：2026-10-24
> 用途：**怎么实现**——系统边界、依赖、优先级。
> 前提：世界观尚未定调，M0 切片的作用之一就是帮它定调。

---

## 0. 第一原则

> **系统不认识世界，世界只是数据。**

但不能推到极端。有些系统**本身就是修仙**——做成通用引擎，游戏就没味道了，成本还翻倍。所以先分层，再谈抽象。

---

## 1. 三层分离

| 层 | 内容 | 换世界观时 |
|---|---|---|
| **骨架层** | 时间、存档、资源、修正器、活动、条件、事件调度 | 完全不动 |
| **修仙层** | 境界、寿元、灵根、突破、丹道、心魔、因果、气运 | 机制不动（这就是游戏） |
| **皮肤层** | 门派、人名、地名、物品名、剧情、美术 | 全换 |

判断标准：换题材机制完全不变 → 骨架；机制能换皮但换了就变味 → 修仙；只有名字 → 皮肤。

**修仙层现在就要做对，皮肤层一律不许进代码。**

---

## 2. 一个必须先承认的冲突

| | idle 要的 | 修仙要的 |
|---|---|---|
| 趋势 | 越来越快 | 越来越难 |
| 感受 | 爽、顺、滚雪球 | 卡、赌、代价 |
| 失败 | 不存在 | 必须有 |

不处理，游戏会在中期撕裂：要么变成纯数值膨胀，要么变成硬核卡关。

**解法：呼吸节奏。**

```
境界内（炼气三层 → 九层）  =  idle 逻辑：数值增长、解锁、自动化、爽
境界间（炼气九层 → 筑基）  =  修仙逻辑：瓶颈、准备、赌、失败
```

每个境界是"一段爽 + 一道坎"。**突破之所以必须是赌，就是它是两种逻辑的换气口。**

这条决定了所有系统的形态：**任何系统都要同时支持"顺"和"卡"两种状态。**

---

## 3. 系统清单

### P0 · 骨架（M0 必须有）

| # | 系统 | 职责 | 世界耦合 |
|---|---|---|---|
| 1 | **Core** | 固定步长 tick、暂停、倍速、游戏内日历 | 无 |
| 2 | **State + Save** | 唯一状态源、序列化、版本迁移、离线结算 | 无 |
| 3 | **Resource** | 资源容器、增减、上限、变更信号 | 无 |
| 4 | **Modifier** | 修正器链 base → flat → increased → more | 无 |
| 5 | **Activity** | 单任务状态机：start/tick/finish/interrupt/resume | 低 |
| 6 | **Condition** | 统一条件求值器 | 无 |
| 7 | **ContentDB** | 数据加载、Schema 校验、热重载 | 无 |
| 8 | **Cultivation** | 打坐 → 修为 → 境界层数 | **高** |
| 9 | **Lifespan** | 寿元上限、时间流逝、衰老、临终 | **高** |

### P1 · 循环（M1）

| # | 系统 | 职责 | 耦合 |
|---|---|---|---|
| 10 | **Breakthrough** | 突破判定、三档结果、种子锁定 | 高 |
| 11 | **Inventory** | 物品栈、堆叠、筛选、可见性 | 无 |
| 12 | **Event** | 调度、权重、冷却、选择、delayed 因果 | 低 |
| 13 | **Dwelling** | 洞府等级、灵气浓度 | 中 |
| 14 | **Alchemy** | 丹方、成功率、丹毒 | 中 |

### P2 · 厚度（M2–M3）

| # | 系统 | 职责 | 耦合 |
|---|---|---|---|
| 15 | **Combat** | 一次结算、战报、越阶、对手价值递减 | 中 |
| 16 | **Aptitude** | 天赋六维（灵根配比 / 体质 / 筋脉 / 悟性 / 神识） | 高 |
| 17 | **Technique** | 功法、主修/兼修 | 高 |
| 18 | **Daoheart** | 心魔、心境系数 | 高 |
| 19 | **Karma** | 因果记录、劫的形式、NPC 态度 | 高 |
| 20 | **Fortune** | 气运、命格、望气、卜卦、择日 | 高 |
| 21 | **Sect / Relation** | 宗门经营、人脉、道友入队 | 中 |
| 22 | **Exploration** | 游历、地点、机缘 | 中 |
| 23 | **Clone** | 分身、任务编排 | 中 |

> **两条边界**
> **Karma**：只是一个带符号的善恶记录，用于劫的形式、NPC 态度、事件分支。**不承载成仙路径**——凡人成仙是"品格凝结灵根"的 NPC 传说，别做成强度轴。
> **Fortune**：**不显示数值**。只通过望气、批语、卦象表达。见 `03-天赋与气运.md`。

## 4. 依赖关系

```
Core ─┬─ State ─┬─ Resource ── Modifier
      │         ├─ Lifespan
      │         └─ Condition
      ├─ ContentDB
      └─ Activity ─┬─ Cultivation
                   ├─ Alchemy
                   └─ Exploration

Breakthrough ← Cultivation + Lifespan + Modifier
Event        ← Condition + State(flags) + Activity(可打断)
Combat       ← Modifier + Inventory + Event + Aptitude
```

三条硬约束：

1. **Core 不依赖任何东西**，它不知道修仙存在
2. **Cultivation 不认识 UI**，只发信号，不碰节点
3. **Event 不认识具体事件**，只调度，内容在数据里

## 5. 应对"世界观未定"的四条

### 5.1 延迟命名

**未定的世界观不要用具体名词填空。**

| 别写 | 先写 |
|---|---|
| 青崖洞 | 洞府 |
| 天元历三年 | 第 3 年 |
| 聚气丹 | 丹药（品级 A） |

现在编的名字，定调后要改两遍。**能不命名就不命名。**

### 5.2 一切文本走 key

中文也走 key。现在做成本为零；以后做是全部文案返工。

### 5.3 境界是结构，名字是数据

不写死"炼气/筑基"。做成 `realm[0..5]`，每层有 `tier_count`、`lifespan_cap`、`unlocks`，名字在 `realms.json`。

同理，修炼体系**暂不区分**，但存档里留 `system: "qi"`，否则以后要写迁移脚本。

### 5.4 世界包目录

```
data/
  worlds/
    default/       ← 当前世界，可整体替换
      realms.json / items.json / recipes.json / events.json / names.json
  balance.json     ← 与世界观无关的数值
```

换世界观 = 换一个目录，代码不动。

## 6. 防过度抽象：以 Activity 为例

"世界未定"最容易导致的错误是**把所有东西做成万能引擎**——你会得到一个能跑任何 idle 的框架，但它没味道，成本还翻倍。

`Activity` 不要做成 `Activity(rate, duration)` 这种万能公式，那会逼你把所有玩法压成同一个形状：

```
Activity（结构：时长/进度/可中断/产出结算）
  └─ Behavior（策略，数据驱动）
       打坐：持续产出，受灵气浓度修正
       采药：一次性产出，有成功率，有副产品
       炼丹：消耗材料，有成功率，有失败产物
       游历：时长较长，期间持续触发事件
```

**结构共享，行为分离。** 以后加炼器、画符、驯兽只是加一个 Behavior。

---

## 7. M0 的 UI 应该故意做丑

世界观没定 = 视觉语言也会变。现在做的水墨 UI、字体、图标，定调后大概率要重做。

M0 用 Godot 原生控件，只求"看得清、点得动"，精力全砸在数值手感上。

**等切片跑通、世界观定调，再谈美术。** 这条能省掉一次完整的 UI 返工。

## 8. M0 的系统范围

| 系统 | 做到什么程度 |
|---|---|
| Core | tick 0.1s、暂停、1×/2×/4× |
| State + Save | 存/读、version 字段、离线结算 |
| Resource | 4 种资源（灵气/修为/灵石/药材） |
| Modifier | 3 层（base/flat/increased） |
| Activity | 2 个行为（打坐/采药），含 interrupt/resume |
| Condition | 求值器可用，暂无调用者 |
| ContentDB | 加载 2 个 JSON，校验失败即报错 |
| Cultivation | 炼气一→三层 |
| Lifespan | 上限 + 时间流逝 + 1 种损伤（突破失败） |
| Breakthrough | 炼气三层→四层，一次会失败的判定 |

**M0 不做**：背包 UI、炼丹、事件内容、战斗、天赋六维、气运、宗门。

**验收标准不是"功能多"，而是：能连续玩 15 分钟，并且中途产生过一次真实的犹豫。**
