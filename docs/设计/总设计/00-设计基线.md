# 00 · 设计基线

> 版本：v2.0　更新：2026-10-24
> 用途：**游戏是什么**——玩家能感受到的规则与体验。
>
> **阅读顺序**：README 总览 → 00 玩法 → 01 世界 → 03 天赋 → 02 技术 → 04 伏笔
>
> **决策标记**：`可逆` 改数据即可 / `半可逆` 要改多个系统 / `不可逆` 推翻重做。

---

## 0. 一句话

**用一具凡人的身体，在有限的一生里，走到世界的尽头。**

不是"打坐涨数字"，也不是"用命换东西"。

---

## 1. 三条支柱

| # | 支柱 | 含义 | 反面 |
|---|---|---|---|
| P1 | **寿元是时钟，不是货币** | 你只能让它流逝，不能花它。压力来自"错过"，不是"消耗" | 每个按钮都标价"耗寿 30 年" |
| P2 | **境界是质变** | 每境是身体改造的一个阶段，解锁新规则 | 筑基 = 炼气 × 10 |
| P3 | **斗法是磨练** | 修与用分开：打坐是"修"，斗法是"用"的磨练。斗法带来实战经验、心境历练、战利品 | 斗法只是惩罚，或斗法能直接刷修为 |

> P3 修正过两次。第一次定义成"代价"（错），第二次定义成"验证"（也不够）——**斗法当然是成长的一大助益**。准确的说法是：斗法练的是"用"，不是"修"。它能让你变强，但变强的方式是"会用"，不是"道行高"。

## 3. 时间与寿元

### 3.1 时间只在行动中流逝

| 规则 | 说明 |
|---|---|
| 思考时静止 | 玩家在菜单前犹豫多久，世界都不动 |
| 行动有耗时 | 打坐一日、游历三月、闭关十年 |
| 执行后前进 | 时间在行动完成时结算，不在选择时扣除 |

### 3.2 寿元 = 上限 − 已过时间

**寿元只有两种减少方式**

| 方式 | 说明 |
|---|---|
| 时间流逝 | 唯一途径。活了多久，就少了多少 |
| 上限被损伤 | 突破失败、重伤、根基受损——钟被砸短了，不是被花掉 |

**玩家永远不能"花寿元"。** 这是整套设计的分水岭：没有"花 30 年换天赋"的按钮，只有"这件事要花三十年"的行动。

| 境界 | 寿元上限（基准） |
|---|---|
| 炼气 | 120 |
| 筑基 | 200 |
| 金丹 | 500 |
| 元婴 | 1200 |
| 化神 | 3000 |
| 渡劫 | 10000 |

寿元上限由**境界**决定，不由灵根决定。延寿 = 把钟的刻度加长。

### 3.3 时间前进，世界会变

这是沉浸感的真正来源，也是压力的来源：

| 你闭关三十年 | 世界发生了什么 |
|---|---|
| 人 | 故人老了、死了；当年的孩童成了家主 |
| 事 | 某场百年一遇的秘境在二十年前开过了 |
| 地 | 山门搬了，村子变成了镇 |
| 势 | 你得罪的那个小门派，已经成了大宗 |

**压力不是"我还剩多少年可以花"，是"我做的这件事，会让我错过什么"。**

### 3.4 不制造紧迫感

- 不做每秒跳动的红字倒计时
- 不做实时衰老（玩家思考时时间不走）
- 寿元以"年"为单位静态显示
- **默认情况下不会寿元将尽**：不铤而走险 + 运气不极差，就死不了
- 剩余低于 10% 时才变色，并给出明确出路

## 4. 核心循环

| 尺度 | 循环 | 玩家动作 |
|---|---|---|
| 秒–分 | 选活动 → 耗时间/耗材 → 产出 → 速率提升 | 切换活动 |
| 分–时 | 修为满 → 备齐条件 → 赌突破 → 境界提升 | 攒资源、选时机 |
| 时–天 | 扩建洞府 → 分工自动化 → 渡劫飞升 | 规划、编排 |

**四条铁律**

1. **一人一时只做一事**。并行必须由分身/傀儡/道友承担。
2. **突破必须会失败**。
3. **没有无输入的产出**。
4. **世界在时间里变化**。时间不是数字，是代价。

**转化链**

```
洞府灵气 × 功法效率 × 灵根契合 × 心境系数  →  修为/秒
修为满 + 心境达标 + 外物（丹药/阵法/护法）  →  突破判定
境界提升  →  解锁新规则 + 寿元上限抬升
```

## 5. 资源体系

| 层 | 内容 | 性质 |
|---|---|---|
| 环境层 | 灵气浓度（洞府、灵脉、时辰） | 全局乘数，不是资源 |
| 基础层 | 灵气、灵石、药材、矿石、妖兽材料 | 可采集、可交易 |
| 加工层 | 丹药、法器、符箓、阵盘 | 消耗基础层 |
| 元资源 | 修为、悟性、寿元、心境、因果 | 不进交易，只影响规则 |

**铁律：灵石 ≠ 修为。** 灵石可花、会贬值；修为只增不减、不可交易。一旦灵石能买修为，修仙感当场崩塌。

**数值规模不设硬上限**，按成长曲线需要来定。真正的约束在 UI 呈现（见 §11），不在数值本身。

## 6. 境界与突破

| 境界 | 层数 | 解锁 |
|---|---|---|
| 炼气 | 九层 | 打坐、采药、基础丹方 |
| 筑基 | 初/中/后/圆满 | 辟谷、并行槽 +1、可离洞游历 |
| 金丹 | 一品–九品 | 结丹品级决定隐藏上限；识海（自动化雏形） |
| 元婴 | — | **分身**（真正的自动化）；夺舍 |
| 化神 | — | 领域、势力 |
| 渡劫 | — | 飞升 |

境界的定义是**身体改造的阶段**。修炼体系暂不区分，但数据层留 `system` 字段（见 02 §5.3）。

### 6.1 突破 = 工程风险，不是纯赌

流程：修为满 → 选辅助（丹药/阵法/护法）→ 判定 → 三档结果。

| 结果 | 后果 |
|---|---|
| 成功 | 境界提升、寿元上限抬升、解锁新规则 |
| 失败 | 修为倒退 + 重伤卧床（时间流逝）+ 根基受损（寿元上限降低） |
| 走火入魔 | 心魔 +、功法受损、可能跌落小境界 |

**注意失败的代价不是"扣寿元"，是"伤根基"。** 前者是消费，后者是损伤——玩家的钟被砸短了，而不是被拿走了一截。

四条规则，缺一条就崩：

| # | 规则 | 防的是什么 |
|---|---|---|
| 1 | 显示区间，不显示精确值（"六成到八成"） | 精确值会让玩家算出最优解 |
| 2 | 显示影响因素清单，不显示权重 | 知道丹药有用，不知道加多少 |
| 3 | 保留一个不可控变量（天时/身体/心魔） | 做完全部准备后仍要赌那两成 |
| 4 | 准备有边际递减 | 防止把成功率顶到 99% |

**技术前提**：判定在"确认突破"瞬间用一次性种子锁定并立即落盘，读档不可重算。

## 7. 开局与天赋

### 7.1 开局完全固定

凡人、五行平庸、无背景、无资源、无靠山。不 roll、不选难度、不出身。

理由：idle 的乐趣在长期经营，起点差异会让攻略失效；"废柴开局"本身就是最强的修仙原型；单机没有排行榜，起点相同的价值是平衡可控。

### 7.2 天赋是六维，且前五维全部可成长

| 维度 | 影响 | 提升手段 |
|---|---|---|
| **灵根**（五行配比） | 功法效率、丹道亲和、属性克制、突破瓶颈 | 灵果、丹药、功法、洗髓 |
| **体质** | 元气上限、抗伤、突破承受力 | 淬体功法、药浴、天材地宝 |
| **筋脉** | 灵气吞吐速率 | 通脉、丹药、机缘 |
| **悟性** | 功法领悟、突破成功率 | 读经、游历、静坐 |
| **神识** | 炼丹/阵法/斗法精度 | 静坐、秘法、丹药 |
| **气运** | 事件权重、遇敌强度、机缘率、NPC 态度 | **不能练，只能应** |

**前五维是"你是什么"，气运是"世界怎么看你"。** 所以气运虽然列在天赋里，机制完全不同。

**灵根不是"越少越好"，是五行配比。** 没有绝对好坏，只有适配。详见 `03-天赋与气运.md`。

### 7.3 提升天赋不靠按钮

没有"洗髓"按钮。有的是世界里的东西：

| 手段 | 特点 | 代价 |
|---|---|---|
| 灵果 | 一次性、稀有，提升某一系 | 有产地、要寻访、会被人抢 |
| 丹药 | 一次性 | 材料 + 炼丹 + 抗性 |
| 功法 | 持续、缓慢 | 占用主修位 |
| 洗髓 | 一次性、极险，重排配比 | 长期闭关 + 失败风险（不扣寿元） |
| 机缘 | 顿悟、传承 | 不可控 |

### 7.4 身份不是选的，是挣的

宗门、人脉、靠山在游戏内获得——中期被某个门派看上，或被拒之门外。

### 7.5 可补的是资源，不可补的是身份

| 可补 | 不可补 |
|---|---|
| 五行配比、体质、筋脉、悟性、神识 | 主修功法（只能一条，build 锁定） |
| 功法（可兼修） | 道心（选择决定，不可回退） |
| 法器、丹药 | 因果（做过的事永远记着） |

## 8. 战斗

**定位**：斗法是成长的一大助益。修与用分开——打坐是"修"，斗法是"用"的磨练。

### 8.0 斗法给什么

| 产出 | 说明 | 强度 |
|---|---|---|
| **实战经验** | 提升功法熟练度（同境界战力） | 主要 |
| **心境历练** | 提升突破成功率、抗心魔 | 次要 |
| **战利品** | 资源、功法、法器 | 直接 |
| **感悟** | 小概率触发顿悟（悟性） | 稀有 |

**唯独不直接给修为**——修为是"道行"，斗法是"用法"。如果斗法能给修为，idle 的节奏就乱了，游戏会变成刷怪。

### 8.0.1 对手价值递减

同一层次的对手，重复战斗的收益**指数衰减**：第一次收获满，第十次几乎没有。

所以想靠斗法成长，就必须**找更强的对手**——而更强的对手意味着更高的风险。

**这就是"以战养战"的正循环，它天然自带刹车。**

来源：游历、剧情、宗门任务、秘境、仇家、天劫。

### 8.1 开战前是唯一的操作点

| 选项 | 代价 |
|---|---|
| 战 | 消耗元气，可能重伤 |
| 避 | 可能被追上，损失声望/机缘 |
| 示弱送礼 | 损失灵石/材料，保命 |
| 用物 | 消耗符箓/丹药，改变战力 |
| 请援 | 需人脉，欠人情 |

全部策略性集中在这一个决策点，之后全自动。

### 8.2 结算

3–6 回合自动结算，输出文字战报 + 场景光效，可跳过。
属性：攻 / 防 / 速 / 元气 / 暴 / 五行抗性。

**修为 ≠ 战力**。修为决定境界，战力来自功法、法器、丹药、阵法、体系。炼气九层持上品法器可以斩筑基初期——这个爽点必须留着。

### 8.3 越阶

境界差每级 ×2.2（乘数不是加法）。跨一个大境界 ×4.8，几乎必败。留窄缝，不给无脑越阶。

### 8.4 代价

| 代价 | 表现 |
|---|---|
| 元气 | 短期资源，打坐回复 |
| 重伤 | 疗伤要时间——时间流逝，世界在变 |
| 结果 | 胜 / 重伤遁走 / 道消（真死，这一世结束） |

**斗法不扣寿元，只消耗时间。** 你躺了三年养伤，出来发现仇人已经死了——这才叫代价。

## 9. 剧情

### 9.1 结构：弱线性

六章，每章 5–8 个主线节点（门槛）+ 事件池（填充）。

**弱线性的意思**：主线提供方向，不提供唯一路径。玩家可以晚十年再去做主线，也可以先去别处；主线不锁死其他玩法，只是某些门需要它才开。

| 章 | 名 | 骨架 |
|---|---|---|
| 一 | 入门（炼气） | 凡人 → 得残卷 → 采药维生 → 首战 → 入宗门或被拒 → 筑基 |
| 二 | 立足（筑基） | 门派任务 → 首个秘境 → 结交道友/结仇 |
| 三 | 立名（金丹） | 宗门大比 → 结丹品级抉择 |
| 四 | 立势（元婴） | 分身 → 势力 → 旧仇清算 |
| 五 | 立道（化神） | 道之争 → 天劫前夜 |
| 六 | 飞升（渡劫） | 渡劫 → 飞升 |

> 章节骨架是占位，世界观定调后需重写。

**剧情长在活动上，不长在关卡上**：事件挂在活动/地点上，按条件过滤触发。

### 9.2 事件数据

```json
{
  "id": "evt_cave_outsider",
  "weight": 10,
  "cond": ["realm >= 1", "flag.has_cave == true"],
  "cooldown": 3600,
  "title": "有人倒在洞口",
  "body": "一名散修伏在石阶上，气息将绝。",
  "choices": [
    { "text": "出手相救", "cost": { "cultivation": 200 },
      "gain": { "karma": 1, "flag.saved_stranger": true },
      "delayed": [{ "after_days": 30, "event": "evt_stranger_returns" }] },
    { "text": "视而不见", "gain": { "karma": -1 } }
  ]
}
```

`delayed` 是因果的载体：**今天的选择，三十年后回来找你**。

### 9.3 三个接口必须现在留

| 接口 | 作用 | 第一版状态 |
|---|---|---|
| 世界状态 flags | key-value 字典，任何系统可读写 | 空字典，但要真的存在 |
| 统一条件求值器 | `"realm >= 3"` / `"flag.x == true"` 一套语法 | 实现求值器，暂无调用者 |
| 活动可打断 | 状态机 `start/tick/finish/interrupt/resume` | 必须有 `interrupt()` 且能 `resume()` |

**五个触发点**（第一版空实现）：活动完成 / 突破成败 / 进入新地点 / 游戏内每月 / 寿元跌破阈值。

### 9.4 事件的原则

**事件不该"推进"修炼，该"打断"修炼。** 如果它只是给资源，就退化成随机宝箱。

事件必须低频（10–20 分钟一次）、高影响、有代价。

## 10. 结局

**第一版：单一结局（飞升）**，但数据结构是结局表（`endings.json`），以后加分支不改代码。

**通关必须给"回顾"**：这一世用了多少年、走到哪一步、错过什么、救过谁杀过谁、关键人物的结局。

这是 idle 唯一的收束快感。没有它，几十小时换来一个黑屏。

## 11. UI

三栏 = **我 / 行 / 有**。

| 区 | 职责 | 频率 |
|---|---|---|
| 左 | 我是谁、我怎样 | 低频检视 |
| 中 | 我正在做什么 | **高频，恒为视觉重心** |
| 右 | 我有什么（AE2 式终端） | 低频检视 |

### 11.1 总原则：默认沉浸，按需精确

带数字的进度条出戏，因为它把"修仙"翻译成了"报表"。所以分三层：

| 层 | 表现 | 何时出现 |
|---|---|---|
| 默认层 | 光晕浓度、呼吸节奏、气感、气息 | 一直在 |
| 提示层 | 悬停显示精确数值 | 鼠标停留 |
| 详情层 | 完整数据面板 | 主动打开 |

修为不写"412 / 900"，写"气机充盈，尚差一线"。想看数字就悬停。

### 11.2 其他约束

1. 左右可折叠，中栏永远最大
2. 中栏是**可替换容器**，允许被全屏接管
3. 右栏支持"全量定义 + 可见性过滤"——未持有的物品显示为剪影

### 11.3 PC 横屏的硬要求

| 要求 | 原因 |
|---|---|
| 1280×720 起，1360×765 为基准 | 兼容小屏笔记本 |
| 全键盘：`1–9` 切活动、`Space` 暂停、`Tab` 切面板 | 放置游戏是高频切换的游戏 |
| 悬停即详情 | AE2 的心智模型就是悬停 |
| 窗口 / 无边框 / 全屏三态 | PC 放置常驻后台 |
| 启动时给离线回执 | 关掉再打开是常态 |

> 视觉语言（水墨、字体、图标）待世界观定调后再做，M0 用原生控件。

## 12. 技术架构

### 12.1 四层

| 层 | 职责 | 约束 |
|---|---|---|
| 表现层 | UI、场景、演出 | 只发指令、只订阅状态；10Hz 节流刷新 |
| 系统层 | 修炼/炼丹/战斗/事件/突破/存档/离线 | 通过 SignalBus 通信 |
| 模拟层 | GameState、TickEngine、Modifier | **纯 GDScript，不继承 Node**，可 headless |
| 数据层 | 物品/丹方/境界表/事件池/敌人表 | JSON + Schema，代码里不出现具体物品名 |

### 12.2 六条技术铁律

1. **在线与离线共用同一条公式**——两套算法是放置游戏最常见的致命 bug
2. **内容 100% 数据驱动**——20 个物品时就要做
3. **Modifier 分层**：`base → flat → increased → more`
4. **存档 JSON + version + migration**，自动存 + 关键节点存
5. **模拟层可测试**：headless 跑"模拟 1 小时"，断言产出曲线
6. **不可回滚的随机**：突破、事件判定用一次性种子锁定并即时落盘
